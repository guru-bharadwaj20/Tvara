## Known performance limitations

- The served executor dequantizes all weights to float32 at load and runs scalar matvec on one thread; quantized and SIMD kernels are not on the model path ([kernels.md](kernels.md)).
- Prompt prefill is one C ABI call per token; there is no batched prompt matmul.
- The HTTP server does not use the scheduler, prefix cache, or speculative decoding.
- Speculative verification runs target steps serially and rollback re-decodes the last kept token; it was slower than plain decoding in every measured row.
- AVX-512 and ARM NEON paths have not run on supporting hardware ([avx512-validation.md](avx512-validation.md), [arm-validation.md](arm-validation.md)).
- No pretrained model has been benchmarked; tiny fixtures exaggerate per-call overhead.
